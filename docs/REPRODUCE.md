# Reproducing the protocol findings

The LUT commands were identified in Panasonic's **LUMIX Lab for Android 3.1.0** (`com.panasonic.jp.lumixlab`,
versionCode 22), downloaded from Google Play. Its split APKs are signed with the Play App Signing certificate
SHA-256 `6e8e62b2206759c021bf316feda8bfd814007f46aba8f1fd5097aa40c9017e03`. No app code or assets are in this repo;
to check a newer app version yourself:

1. Get the APK from Google Play for your own device, decompile with `jadx --no-res`.
2. Look for (obfuscated names in 3.1.0, they change between builds):
   - the PTP operation enum: entries like `LumixLutSendFileData(-26332)` (signed 16-bit) → `docs/CODES.md`
   - the request builders using it (`LumixLutStartFileData` + 256-byte ASCII name; `LumixLutSendFileData` with the
     file length; `LumixSetParamInfo` with `RenameLUTFile`/`SortLUTFile`/`DeleteLUTFile`)
   - the `GetLutInfo` reply parser (272-byte records)
   - the transfer flow: over USB the buffer size equals the file size (one transfer)
3. `strings` on the native library (`libllc.so`) shows the `.cube` tags: `#LUMIXPHOTOSTYLE %s`, `#GRAINEFFECT L%d`,
   `#COLORNOISE L%d`, `#SHARPNESS L%d`, `#NOISEREDUCTION L%d`, `TITLE "Generated by LUMIX Lab"`.
4. Verify against a camera with `control/lumix_lut.py selftest` (read-only) before writing anything.

Decompiling for interoperability is permitted in the EU (Software Directive Art. 6); publish findings, not code.
